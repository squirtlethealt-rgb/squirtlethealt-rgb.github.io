⚠️ CRITICAL DESIGN TRADEOFFS FLAGGED (FULL CHUNKY OVERRIDE VS SRS)

1. Active Coding Legibility vs Chunky Playfulness:
While headers, frames, and buttons use Lilita One and candy colors, the interior code editor text must remain an ultra-clean monospace font (IBM Plex Mono / Cascadia) with comfortable line-height (1.7) and high-contrast dark slate backdrop. Putting cartoon typography inside the code input itself would severely harm syntax recognition for 11–16 year olds.
2. Socratic Error-Hint Distinct Semantic Palette:
In candy UI, red is used for Close/Danger, and Green for Play. If the Socratic hint used bright red, students would panic and interpret it as a failure alarm. We assigned it a warm golden-parchment and soft indigo palette with golden-ratio (~1:1.618) width, making it feel like an inviting clue card.
3. Vertical Real Estate on School Chromebooks:
3.5px–4.5px borders and 7px shadows add height. We engineered compact HUD pills and responsive toolbars so the code editor and terminal always get maximum vertical space.
4. Dense Tabular Data vs. Thick Borders (Data Science):
In pandas dataframes with 6+ columns, placing 3.5px borders around every individual cell quickly crowds out numbers and causes horizontal clipping. Solution: The exterior table frame and header row use the full chunky candy treatment (gold fill, ink borders, hard shadow), while interior cell dividers use lightweight 1px–1.5px lines with horizontal scroll (overflow-x: auto) to preserve data scannability.
5. Cell-Based Shadow Stacking & Scrolling Fatigue:
Stacking 7px drop shadows across 15+ consecutive notebook cells creates visual heavy-handedness. We tuned cell blocks to 3.5px borders with 4.5px shadows, highlighting only the currently active cell with a green candy border, and integrated floating "+ Add Cell" divider affordances between blocks.
